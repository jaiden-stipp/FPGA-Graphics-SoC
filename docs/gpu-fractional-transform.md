# Fractional terrain model translation: GPU-FRACTION-001

Status: implemented optional contract for ARCH-UPGRADE-001 Stage 1. Scoped terrain equivalence and timing checks pass; physical packing experiments regress and are not promoted. See [results](architecture-stage-0-1.md). The legacy protocol remains valid.

Capability discovery: existing `SOC_CPU_FEATURES` bit 31 advertises the presence of the GPU capability register; bit 0 remains MUL. Test bit 31 before reading the new address so old hardware does not receive an unsupported MMIO read. Then read the read-only `SOC_GPU_FEATURES` at audited offset `0xa8` in the existing `0x40000000` MMIO window. Bit 0 advertises `draw-mesh-fraction-v1`; other bits are reserved zero. Opt-in packages declare this feature and must reject incompatible hardware before issuing the new command. Legacy packages never require it.

Wire opcode **13**, command framing/version/CRC unchanged. Payload length **28 bytes**: existing DRAW_MESH 25-byte payload (handle and twelve big-endian signed int16 model values), followed by unsigned X/Y/Z remainder bytes. Internal opcode 11 is newly assigned; internal payload extends to 224 bits with remainders in bits 223:200. All existing payload slices remain unchanged. This command is legal only during a frame, with the same mesh-readiness, upload exclusion and draw completion rules as legacy DRAW_MESH.

For component r, output = floor((dot(local_vertex, model_row) + remainder[r]) / 256) + integer_translation[r]. Legacy DRAW_MESH supplies remainder zero, preserving the old result exactly. The remainder is captured with the draw matrix, so later commands cannot change an active draw.

CPU reference: floor(4 * dot(local_vertex + chunk_origin - player, view_row) / 256) + view_translation. Let S = 4 * dot(chunk_origin - player, view_row). Set model coefficients to 4 * view coefficients, integer translation to floor(S/256) + view_translation, and remainder to S mod 256 in [0,255]. Signed arithmetic shift gives floor division, including negative S. This yields the exact CPU transform with one combined floor.

Arithmetic: source/local and model coefficients stay signed int16. Products remain signed int32 and the summed products/remainder use signed 34-bit arithmetic. CPU safe admission restricts player to signed int16, view coefficients to [-256,256], original source bounds to the existing bounded world format, and local vertex bounds to int16. Model translation must fit the existing range. The eight source-world box corners must prove camera coordinates within existing signed limits and wholly inside near 257, far 30000, focal 256 side planes. Cross-frustum or unproven chunks retain CPU clipping. No saturation or relaxed camera policy is permitted to raise admission counts.

No changes to actor posing, collision queries, source triangles, winding, game timestep, or mesh capacities. Fraction support is an optional build/target capability; CPU-direct and legacy-safe paths remain selectable. Source-neutral tight packing splits at existing spatial-cell boundaries and retains the exact legacy sorted face order and source-face IDs.

Required verification: signed/negative fractional transformations, zero-fraction legacy equivalence, 0/255 residues, maximum accepted bounds, malformed command length/CRC, old-package compatibility, output stability under backpressure, randomized CPU/GPU equivalence, source-face preservation, and complete terrain color/depth comparison including equal-depth overlap. Package checks, measured admission/upload costs and complete timing must pass before deployment.

Timing implementation: the first fit failed by 0.250 ns on mesh component selection to transformed Y output. A product-sum register stage separates multiplication/selection from fractional rounding, translation and saturation. It adds one cycle per component (nine cycles per triangle) to both legacy and fractional resident mesh drawing; output values and ordering remain unchanged. Timing and physical workload cost must be measured before acceptance.
